# lisploop --- results

## Milestone 1: search and the synthesis kernel

27 October 2026. Implementation and experiment record for milestone 1 of plan 4.

A dependency-free Common Lisp implementation of [plan 4](plan4.md)'s first
milestone: typed data and programs, isolated execution, finite-description
enumeration, resumable checking, and explicit description/work accounting.
This retains the SBCL implementation choice from plans 1 and 2; milestone
numbers follow plan 4. The algebra-discovery experiments belong to milestone 4.

```sh
make test                       # contract checks and independent tiny references
make m1                         # the reproducible GF(5) experiment and trace
make results.pdf                # build this document with Pandoc
sbcl --load load.lisp            # inspect the kernel at a REPL
```

Tested with SBCL 2.6.4. No Quicklisp, Python environment, or external libraries
are needed. The default `make` target builds the planning PDFs and `results.pdf`
using the same Pandoc/LaTeX settings.
Loading is relative to the script, so `sbcl --script /path/to/tests.lisp` also
works from another directory.

## First result

The complete GF(5) table for `y = a + 2*b` is generated by the simulator.
The learner receives its declared input/output frame, field vocabulary, and
bounds; the oracle program is kept outside learner inputs.

At 41 bytes, the enumerator completes the bound without finding a predictor.
After interruption and extension to 71 bytes, it finds `a + (b + b)`, along with
nine other valid expressions. Isolated decoding and replay succeed on all 25
inputs. Resumed and uninterrupted searches have identical candidates and work
totals. This is exhaustive validation over GF(5), not a claim about integers.

| Representation | Description bytes | Execution work on 25 inputs |
|---|---:|---:|
| First verified formula | 71 | 2,000 |
| Packaged function lookup | 375 | 22,325 |
| Literal ordered output sequence | 65 | Different, whole-object task |

The formula does **not** compress the 65-byte output sequence under this
encoding. The lookup comparison includes an executable function of `(a,b)`;
the output-sequence comparison assumes an ordered whole-object target. Neither
comparison demonstrates a search speedup. Completing the 71-byte search costs
876,490 work units, including failures; its first solution arrives at 31,138.
Observation generation, baseline construction, and independent replay add
29,825 units to this experiment. Wall time and a separate supplied-decomposition
control appear in [milestone1.txt](milestone1.txt). Regenerate that record with
`sbcl --script milestone1.lisp > milestone1.txt`.

The objectives are declared before the experiment: pure description
`(lambda_run, lambda_search) = (0,0)` and positive work `(1/100,1/1000)`.
Results include `S`, `W_run`, `W_search`, `J = S + lambda_run*W_run`, and
procedure cost including acquisition. There is no residual in this exact
function-synthesis fixture. Observation generation is charged once; reorientation
charges processing without rerunning the experiment.

## Kernel and interfaces

| File | Responsibility |
|---|---|
| `syntax.lisp` | Types, tagged expressions, simultaneous substitution, canonical codec |
| `sim.lisp` | Deterministic stack machine, explicit errors, work ledger |
| `frames.lisp` | Schema/rows, joint requirements, reorientation, pullback, paid lookups and reconstruction |
| `search.lisp` | Exact-size bottom-up enumerator, resumable verification, candidates and messages |
| `au.lisp` | Typed first-order matching and aligned syntactic anti-unification |
| `fixtures.lisp`, `tests.lisp`, `milestone1.lisp` | Separate oracle fixtures, controls, and experiment |

The only frame is `Frame(schema, rows)`; each row has `key`, `known`, and
`allowed`. Schema inputs are an alist of numeric variable IDs to types. Known
values follow that order. Keys are unique occurrence identities and never enter
the predictor environment. Equal-valued rows with different keys remain distinct.

Types are `:int`, `:bool`, `:index`, `(:gf p)`, `(:tuple ...)`, and `(:seq type)`.
Field literals must already be canonical residues. Arithmetic results are reduced
modulo the declared prime. An integer and a field element remain different typed
objects even if their payloads are equal.

Expressions are `(:lit type value)`, `(:var id type)`, and
`(:app operator (arguments ...))`. An operator is a monomorphic
`(:op name type)` symbol whose signature is fixed by the simulator. Pattern
holes are `(:hole id type)`; an operator hole has a `(:fn inputs result)` type.
Models contain plain typed data and syntax, with no host functions or store
pointers. Treat trees, schemas, rows, and language records as immutable after
constructing a job; the implementation uses structural sharing.

`finite-allowed` retains sets of **whole** values. A correlated tuple set is not
split into independent columns. `predicate-allowed` takes a checked Boolean AST
whose only free variable is the proposed value, ID 0. No Lisp callback is accepted.

`pullback-frame` compiles `A(d(c,z))` into that predicate using encoded observations.
The child's input bindings are separately type-checked against the parent's
declared inputs. Only their computed values reach the child predictor.
`compose-model` substitutes both the binding and child program into the decoder;
the resulting AST includes and pays for all duplicated syntax. Explicit fibers
are used only as independent tiny test oracles, never by search or pullback.

The runtime primitives are arithmetic `+`, `*`, equality, tuple construction,
membership, encoded lookup, and indexed gather. The last four support requirements
and supplied contract controls and are declared prior knowledge. **The default
search grammar enumerates only `+`, `*`, variables, and domain literals.** No
inverse, division, view sketch, AU pattern, or metadata shortcut is supplied to
the GF(5) discovery run.

A lookup requires explicit task permission and actual finite witnesses. For
repeated inputs it intersects the allowed sets; incompatible requirements or
predicate-only requirements cannot fabricate entries. Its entries live in a
priced literal inside the model. Partitions retain an inverse permutation;
quotients retain an index for every occurrence. Their closed `gather` programs
reconstruct the full ordered object from encoded data, including multiplicity.

## Search and interruption

```lisp
(load "load.lisp")
(in-package :lisploop)
(let* ((field (gf 5))
       (frame (orient-observations
               (list field field) '((0 0 0) (1 1 2) (2 2 4)) '(0) '(1)))
       (job (start-search frame (make-language field (schema-inputs (frame-schema frame))))))
  (resume-search job 41 10)       ; cumulative work ceiling, not an increment
  (resume-search job 41 100000)   ; same continuation, larger ceiling
  (search-job-best job))
```

The enumerator advances through canonical byte sizes. It retains every syntax
alternative in typed size buckets. Application sizes are exactly the operator/tag
overhead plus child sizes. Every child is smaller than its parent, so completed
smaller buckets suffice to enumerate every ordered operand combination.
Variables come from a finite declared interface. Field literals are finite;
integer literals are generated lazily by exact signed decimal payload length.
Thus every finite byte bound has finitely many candidates, including over integers.

Each search quantum advances a cursor, constructs/indexes syntax, schedules a row,
or advances one interpreter/checker work unit. The canonical path gets all work;
there is no learned preference or semantic pruning. Failed candidates stop at a
counterexample. Successful candidates check every row and remain available after
an incumbent has been found. Ranking supports a nonnegative execution-work weight.

The VM retains its task stack, value stack, and any partially paid instruction.
Its statuses are `:unknown`, `:value`, and `:error`. A work cutoff leaves
`:unknown`; it is neither a semantic error nor evidence of impossibility.
Increasing the budget continues the same VM, including a suspended checker.

Messages have a call ID, claim, and evidence. A job retains its exact frame and
language; IDs associate candidates and outcomes with that job. `:bounded-exhaustion`
means all candidates through the reported bound have been checked, possibly with
successful candidates. `:cutoff` reports the last *completed* bound and current
phase. Neither is an unbounded refutation. The tiny independent reference checks
both the full syntax set and accepted set at a bound permitting at most one
application. The 71-byte experiment is not an independent optimality reference.

## Encoding and work tariff, version 1

The canonical form is an ASCII S-expression containing only decimal integers and
lists, with one space between elements and no trailing whitespace. `S` is its
byte length. `read-model` decodes it and checks types and input availability;
reader dispatch and reader evaluation are disabled. Encoding fixes the allocation:

| Item | Code |
|---|---|
| Literal, variable, application, operator, hole | Tags `0`, `1`, `2`, `3`, `4` |
| Integer, Boolean, index | Type IDs `0`, `1`, `2` |
| Field, tuple, sequence, function signature | Type tags `3`, `4`, `5`, `6` |
| `+`, `*`, `=`, tuple, membership, lookup, gather | Operator IDs `0` through `6` |

Every literal payload is included recursively. Booleans encode as `0`/`1`;
sequences and tuples encode their complete contents. Model holes have a codec
for pricing patterns but fail executable model validation until instantiated.

The work units are a published abstract tariff, not CPU instructions:

- Preflight costs the encoded AST bytes plus argument payload bytes, per call.
  It includes input/environment validation and syntax checking.
- Variable/application visits cost one; literals cost one plus payload bytes.
- Arithmetic over a fixed prime at most 257 costs one per primitive. Integer
  addition costs the larger operand bit length; multiplication costs their
  bit-length product, with a minimum bit length of one. Larger fields add a
  squared-modulus-bit-length reduction tariff.
- Equality, tuple, membership, lookup, and gather cost one plus input payload
  bytes. Search checks use the same VM and are charged to acquisition.
- Each enumeration cursor operation and scheduling transition costs one;
  syntax construction, validation, and indexing are charged by candidate bytes.
  Pullback/composition charge generated bytes; orientation and supplied views
  charge their data traversal. Matching/AU meter visited terms.

The evaluator prepays an instruction in interruptible work quanta, then executes
its host operation atomically. This is **not wall-clock preemption of a bignum
operation**, a Lisp sandbox for hostile code, or a hardware cost model. Wall time
also includes implementation overhead. Reporting/printing and test harness work
are outside the discovery ledger. `W_run` is a separate future deployment
measurement; replay during acquisition is charged to `W_search`.

## Scope of the controls

`make test` covers the milestone 1 contract and the immediately recommended tiny
syntax controls: input isolation and reorientation, charged lookup replay,
joint predicate/fiber agreement, impossible fibers, partition/quotient reconstruction,
typed substitutions, operator holes, repeated holes, matching, and aligned AU.
The AU reference exhausts the finite flat patterns for all 64 pairs of single
GF(2) applications; it makes no unrestricted abstraction-optimality claim.
Other controls cover exact integer payload bounds, explicit errors, bit-sensitive
work, contradictory rows, shuffling, mid-check interruption, increasing limits,
and repeatable cost totals.

The supplied child trace uses the same search API and composes/rechecks its result.
Automatic view/decoder proposal scheduling, multi-level recursive orchestration,
backtracking, cross-call conflict routing, memory eviction, learned equivalences,
laws, and library learning remain subsequent milestones. No binders, generated
recursion, e-graphs, general graph matching, or semantic pruning are implemented.
Checkpoints currently live in memory, and syntax retention grows with the bound.
